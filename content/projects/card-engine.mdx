## The problem

A card game is a good stress test for object-oriented design: rules, state, and
players change independently, and a fuzzy AI should not make the engine
impossible to reason about.

## Approach

**Separate the concerns.** Players, decks, and game state are modelled as their
own abstractions. A human player and an AI player swap behind one interface so
the engine never special-cases who is sitting in a seat.

**Correctness before cleverness.** The engine is deterministic and testable,
which made trump selection and card-play decisions debuggable instead of
mysterious. Illegal transitions should fail in a test, not only in a long
playthrough.

## What I'd do differently

Push more of the rule surface into explicit state machines and property tests
so illegal transitions fail loudly in CI. Optional: a short terminal GIF on the
cover so recruiters see a hand resolve without cloning the repo.
