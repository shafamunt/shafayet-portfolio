## Problem and outcome

Build a sequential calculator — not a one-cycle ALU. An FSM walks operands
through add, subtract, multiply, and divide and shows a stable result on HEX.

**Outcome:** `FourFuncCalc` datapath + controller for 11-bit two’s-complement
arithmetic, with ModelSim and autograder checks plus a board demo.

## Role

- **Course:** EECS 270, University of Michigan  
- **Spec:** [Project 7 — Sequential Calculator](https://www.eecs270.org/p7_sequential_calculator.html)  
- **My work:** `FourFuncCalc.v`, `TestBench7.v`, `Project7.v` board wiring  
- **Required vs mine:** shared AddSub datapath and abstract STG are course
  architecture; controller refinement, Booth embed, and testbench cases are
  implementation decisions within that frame  

## Architecture

```
SW / KEY / SW[17]  →  FourFuncCalc (FSM + datapath)
                         ├─ HEX operand / result
                         └─ LEDG[8] overflow / ÷0
```

## Technical decisions

**1. One shared AddSub** for all four ops (required datapath).  
**2. Booth multiply** embedded in the datapath (not a direct `BoothMul` instance).  
**3. Divide on magnitudes; sign via XOR;** divisor zero → overflow until clear.  
**4. External signed-magnitude, internal two’s complement** via staff converters.

## Validation

Specific checks run (not a measured coverage percentage):

- ModelSim with state labels on LOAD / ADD / SUB / MUL / DIV paths  
- Autograder checkpoint (ADD/SUB) and final (all four ops)  
- Overflow and divide-by-zero cases in `TestBench7`  
- Board bring-up on DE2-115 / LabsLand — SW entry, KEY ops, HEX result, LEDG[8]
