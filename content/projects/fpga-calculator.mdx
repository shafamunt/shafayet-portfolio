`Verilog` · `FPGA` · `ModelSim` · `FSM` · `RTL`

## The problem

A calculator on an FPGA is not a software `switch` statement — it is a
synchronous machine. Operands load from physical switches, operations fire from
pushbuttons, and results have to survive signed arithmetic, sequencing, and
overflow without glitching the seven-segment displays.

## Approach

**RTL split.** Datapath owns registers, muxes, and the arithmetic units.
Control owns a finite-state machine that sequences load → operate → display
(and clear). Keeping those boundaries strict made ModelSim waves readable.

**Signed path.** Integers move as two's-complement values through
adder/subtractor logic, with multiply and divide as sequenced datapath
operations rather than one combinatorial blob.

**Board I/O.** Switches feed operands and mode bits; keys map to
`+ − × ÷`, `=`, and clear depending on a mode switch — the same physical
buttons, two roles, so the FSM has to know which map is live.
