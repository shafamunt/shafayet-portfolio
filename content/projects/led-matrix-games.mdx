`C/C++` · `MCU` · `LED matrix` · `timing` · `debounce`

## The problem

A game on an LED matrix is a firmware timing problem wearing a fun costume.
The display has to refresh fast enough to look alive, input has to debounce
without eating jumps, and score / difficulty need a clock the player can feel.

## Approach

**Frame the loop.** Each tick: read buttons → update world → draw sprites →
show score. Keep draw cheap so the matrix does not flicker when the "cactus"
or invader count climbs.

**Input.** Edge-detect a held button for jump / fire so a noisy contact does
not look like three presses.

**Difficulty.** Speed or spawn rate climbs with time-alive — same idea as the
Chrome dino ramp, implemented as counters in the loop rather than a desktop
framework.
