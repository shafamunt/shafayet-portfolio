## Problem and outcome

Radiation readings around a settlement arrive as noisy 2D matrices (mSv/hr).
People need maps they can trust — intensity heatmaps, discrete safety zones,
and a local smartwatch crop — plus a check for potential tumors in routine
brain scans.

**Outcome:** a MATLAB function set that denoises scans, builds HSV heatmaps and
zone images, drives a `WatchDisplay` crop from GPS + display settings, and
implements `detectTumor` on MRI-style frames.

## Role and context

- **Course:** ENGR 101, University of Michigan  
- **Spec:** [Project 1 — Dealing with Radiation](http://engr101staff.github.io/engr101.org/projects/project1/specs.html)  
- **My work:** `removeNoise`, `heatmap`, `zones`, `WatchDisplay`, `detectTumor`  
- Solo submission; autograded for correctness and style  

## Pipeline

```
scan_radiation(hour)  →  removeNoise  →  heatmap / zones
GPS_data + display_settings  →  WatchDisplay (local crop)
brain scan  →  detectTumor
```

## Technical decisions

**1. Vectorized denoise, not nested pixel loops.** `removeNoise` applies an
averaging neighborhood so the field stays physically smooth without writing
per-pixel MATLAB loops the course discourages. Tradeoff: edge handling needs
care so border cells stay defined.

**2. HSV for continuous intensity; categorical zones for action.** Heatmaps keep
magnitude readable; zones collapse the same data into regions people can treat
as go / caution / stop. Both share the cleaned radiation matrix.

**3. Driver owns I/O; functions stay pure.** Scripts call `scan_radiation`,
`GPS_data`, and `display_settings`; helpers take matrices and return matrices so
unit tests and the autograder stay deterministic.

## Validation

- Course unit tests for `removeNoise`, `heatmap`, and related helpers  
- Autograder public + hidden cases (numeric tolerance via `almostEqual` /
  image compare)  
- Visual checks with `imshow` during development (not inside submitted
  functions)  

## Limitations

Course project scope — synthetic Proxima-b scenario and staff-provided scan
APIs, not a fielded radiation instrument. `detectTumor` is a student-designed
algorithm evaluated against the course test suite.
