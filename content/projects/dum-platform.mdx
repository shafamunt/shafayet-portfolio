## Problem and outcome

The school needed grades, attendance, and admin workflows that used to live in
spreadsheets, with **five access levels** that must not see the same rows. The
platform is **live in production** for **70+ users**. Authenticated grading and
attendance screens stay private; public surfaces are
[safapp.org](https://safapp.org) and [arshad.guide](https://arshad.guide).

  GitHub Actions CI  

## Architecture

```
React (Vite) — five role-differentiated UIs
        │
        ▼
Edge Functions — authentication + privileged operations
        │
        ▼
PostgreSQL (30+ tables) — Row-Level Security
GitHub Actions — 75+ tests gate every deploy
```

## Technical decisions

**1. Enforce access in the database.** RLS so a missing UI check cannot casually
leak another role's rows.

**2. Privileged ops in Edge Functions.** Authentication and privileged writes
run in Edge Functions rather than as unrestricted client-side mutations.

**3. Block deploys with tests.** **75+** tests in GitHub Actions before ship.

## Validation

Production use by **70+ users** across **five** access levels; CI required
green before deploy. The **70+** figure is the supported user-count metric used
everywhere on this site (not weekly-active or interchangeable “active users”
wording).
