## Problem and outcome

The school needed grades, records, and administration offline from spreadsheets,
with **five access levels** that must not see the same rows. The platform is
**live in production** for **70+ users**. Authenticated admin rows stay
private; public product surfaces are [safapp.org](https://safapp.org) and
[arshad.guide](https://arshad.guide).

## Role and context

- **Employer:** Darul Uloom Michigan (Warren, MI)
- **Product:** Arshad — madrasa + masjid modules on the SAF platform
- **Role:** Software engineering intern  
- **Dates:** May 2026 – present  
- **What I personally built / owned:** end-to-end implementation work on the
  role-based app — PostgreSQL schema and RLS, Supabase Edge Functions for
  authentication and privileged operations, React (Vite) UI differentiated by
  role, and GitHub Actions CI with automated tests gating deploys  
- **What stays private:** authenticated admin UI with student PII  

## Architecture

```
React (Vite) — one codebase, five role-differentiated UIs
        │
        ▼
Edge Functions — authentication + privileged operations
        │
        ▼
PostgreSQL (30+ tables) — Row-Level Security at the row layer

GitHub Actions — 75+ tests gate every deploy
```

![Stack from UI through Edge Functions to Postgres RLS](/images/projects/dum-platform/rls.png)

## Technical decisions and tradeoffs

**1. Enforce access in the database, not only in the UI.** Row-Level Security
means a bug or missing check in React cannot casually leak another role's rows.
Tradeoff: harder migrations and more careful policy testing; safer default for
school data.

**2. Put privileged operations in Edge Functions.** Auth and sensitive writes
stay off the client. Tradeoff: more moving parts than a pure client-to-Postgres
app; clearer security boundary.

**3. Block deploys with automated tests.** A grading system that fails quietly
on Monday is unacceptable. **75+** tests run in GitHub Actions before ship.
Tradeoff: slower merge cadence; fewer production surprises.

## Validation

- Production use by **70+** people across **five** access levels  
- CI required green before deploy  
- Manual role checks during development (each tier sees a different slice of
  data)  

## Limitations and next steps

Gallery shots are signed-out Arshad / SAF surfaces (community select, portal
chooser, madrasa login). Authenticated screens with student records stay off
this site. Feature work continues while the school depends on the system daily.
