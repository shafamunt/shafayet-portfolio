## Problem and outcome

The school needed grades, records, and administration offline from spreadsheets,
with **five access levels** that must not see the same rows. The platform is
**live in production** for **70+ users**. Authenticated admin rows stay private;
public surfaces are [safapp.org](https://safapp.org) and
[arshad.guide](https://arshad.guide).

## Role

- **Employer:** Darul Uloom Michigan (Warren, MI)  
- **Product:** Arshad on the SAF platform  
- **Role:** Software engineering intern (May 2026 – present)  
- **Owned:** Postgres schema + RLS, Edge Functions, role-differentiated React UI,
  GitHub Actions CI  

## Architecture

```
React (Vite) — five role-differentiated UIs
        │
        ▼
Edge Functions — authentication + privileged operations
        │
        ▼
PostgreSQL (30+ tables) — Row-Level Security
GitHub Actions — 75+ tests gate every deploy
```

## Technical decisions

**1. Enforce access in the database.** RLS so a missing UI check cannot casually
leak another role's rows.

**2. Privileged ops in Edge Functions.** Auth and sensitive writes stay off the
client.

**3. Block deploys with tests.** **75+** tests in GitHub Actions before ship.

## Validation

Production use by **70+** people across **five** access levels; CI required
green before deploy.
